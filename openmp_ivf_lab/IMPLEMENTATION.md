# 并行实现说明

## 查询级 OpenMP：omp1

一次 batch 调用建立一个 OpenMP 线程团队，用 `parallel for schedule(static)` 分配查询。每个查询独立执行标量中心选择、候选扫描和 Top-k，只写自己对应的输出区间。`--simd` 在进入并行循环前选择标量或 SIMD 模板实例。

`batch=1` 时只有一个查询迭代，因此只有一个线程承担查询计算；增加线程数不能将这个查询拆开。这个情况应与 `omp2` 的候选块并行比较。

## 查询内部任务：omp2

一次 batch 只进入一处 `omp parallel`。`single` 为各查询生成父任务；父任务在同一团队中选择列表、切块、生成距离计算子任务，等待后合并结果。不同查询的父任务和子任务都由这个团队执行。

每个选中列表按索引位置切成长度不超过 `grain` 的连续块。空列表没有块；长列表会拆成多个块；每块末尾为 `min(begin + grain, list_end)`。各块互不重叠且覆盖全部选中列表，每个候选距离恰好计算一次。当前版本对所有非空块生成任务，尚未引入需要实验依据的短任务阈值。

父任务拥有块描述数组、`B*k` 个局部结果和异常记录，其中 B 是这个查询的候选块数。子任务通过 `firstprivate` 获取块编号、查询指针和 k，读共享只读索引，只写自己编号对应的局部结果和异常槽。子任务中的 `TopK` 是该任务的局部对象。

`taskgroup` 等待全部子任务完成后，父任务才读取局部结果、合并或释放数组。外层团队在退出前完成所有查询任务。因此函数返回时，batch 内全部输出已经就绪。任务或线程中的异常被记录，等同步完成后在调用线程重抛；线程创建失败也会先回收已经创建的线程。

### 每块保留 k 个候选为什么足够

比较顺序始终是 `(distance, id)`。如果候选 x 被某块的局部 Top-k 排除，该块内至少已有 k 个候选排在 x 前面，它们在全局比较中也排在 x 前面，所以 x 不可能进入全局 Top-k。对所有局部 Top-k 的并集再取 Top-k，可以得到完整候选集合的相同结果。局部结果中的 `id=-1` 填充项不参与合并；最终候选不足 k 时，`TopK::finish` 统一填充。

局部结果数组占 `B*k*sizeof(Neighbor)` 字节，此外还有块描述、异常记录、中心选择临时空间和活动任务自己的堆。B 增大时，固定结果空间、任务调度次数和合并工作量都会增加。合并检查 B*k 个槽，并用大小为 k 的堆维护全局结果，最坏复杂度为 `O(B*k*log(k))`。grain 的性能取舍需要在正式数据上测量。

## std::thread 对照

每次调用创建 `min(threads, count)` 个线程，把查询按连续且尽量等长的区间分配，处理完后全部 `join`。每个线程复用公共标量中心选择和标量候选距离，不共享 Top-k。线程创建、异常记录和回收都发生在检索函数内部，因而包含在原有计时范围内。请求线程数超过查询数时，省去没有查询的线程；后续统计应区分请求值和实际值。

## SIMD 与检查

候选距离使用 `double` 计算差值、乘积和累加，通过 `omp simd reduction(+:sum)` 归约。距离循环结束后再更新 Top-k。两个 OpenMP 实现默认 `--simd off`，开关同时写入终端和 CSV。串行参考、全库参考、中心选择和 Top-k 比较器保留原实现。

SIFT 坐标为整数，作业规定的数据范围内这些平方距离可用 double 精确表示。新测试覆盖整数坐标、非 SIMD 宽度整数倍的维数和非对齐起始指针。若扩展到任意浮点向量，归约顺序带来的舍入变化还应单独检查，尤其是近乎等距的候选。

`--simd off` 表示使用公共标量源码函数；编译器可能自动向量化，报告中要根据正式服务器的 `make vector-report` 输出描述实际比较对象。Linux 默认保持 `-O3 -std=c++17 -fopenmp -pthread`，不启用 `-ffast-math`。

## 验证与后续实验

`make test` 包含公共代码检查和学生实现检查；学生实现与串行 IVF 比较，`nprobe=nlist` 时与独立全库扫描比较。`make smoke` 用临时合成数据运行真实命令行、SIMD 参数和 CSV 输出。测试输入由固定随机种子生成，合成文件在结束时自动清理。

正式 A–E 和 std::thread 对照由 `scripts/run_all.sh` 运行，线程扩展主表统一使用 `--simd off`，固定大 batch 为 4P。候选数、线程工作量、实际团队/活动线程、任务/数组大小和阶段诊断在独立 stats 模式采集；延迟分位数从正式计时的逐 batch 样本计算。perf 在每次正式重复的检索循环前后启停，预热与结果检查排除在外。具体计量范围、已知数组空间与整个进程峰值内存的区别见 EXPERIMENTS.md。
